# ADR-20260812-001 — Contract-first baseline gates all implementation

**Status:** Accepted

**Owner:** Trinity

**Requirement IDs:** REQ-VAL-001, REQ-VAL-004, REQ-SCOPE-002, REQ-SCOPE-005, REQ-SCOPE-006, REQ-SCOPE-007

## Context

Four agents implement a single vertical slice in parallel: a care-team
experience, a Foundry agent, a synthetic data and governance layer, and the
narrative. The slice crosses every boundary in one run — request, generation,
review, decision, evidence, and an illustrative view. If any two agents disagree
about a field name, an identifier format, or which side owns a safety check, the
disagreement surfaces at integration, which is the most expensive place to find
it and the place where a safety gate is most likely to be quietly dropped to make
the demonstration work.

The charter requires eight shared contracts before implementation and requires
that completion be reported with actual results rather than scaffolding.

## Decision

No implementation work begins until every shared contract exists as a JSON Schema
2020-12 document under `contracts/schemas/`, has at least one valid example, has
negative fixtures for each safety gate it enforces, and passes
`npm run validate:contracts` with a zero exit code.

The contracts are the integration boundary. An agent implements against the
schema, not against another agent's code. Trinity owns every file under
`contracts/`; agents raise change requests rather than editing schemas directly,
so a safety constraint cannot be relaxed as a side effect of unblocking a task.

Negative fixtures are part of the contract, not a test nicety. Each fixture in
`contracts/examples/invalid/` records the reason it must be refused, and the
validator asserts refusal for *that* reason, so a fixture cannot pass by
accident when an unrelated rule breaks.

## Alternatives

- **Prose specification, schemas later.** Rejected. Prose cannot be executed, and
  the charter requires evidence rather than description.
- **Each agent owns the schema for its own boundary.** Rejected. Every schema in
  this slice is shared by at least two agents, so ownership would be contested
  exactly where the safety invariants live.
- **TypeScript types as the contract.** Rejected. The runtime crosses Copilot
  Studio, Power Platform, and Foundry, none of which consume TypeScript types.
  JSON Schema is consumable everywhere in that path and is directly executable.

## Consequences

- Implementation is unblocked simultaneously for all four agents rather than
  serially.
- A contract change becomes a visible, reviewable, single-owner event.
- The validator becomes a hard dependency of the repository, so the tooling
  manifest (`package.json`, `scripts/`) ships as part of the baseline.
- Contract changes during implementation cost a round trip through Trinity. This
  is accepted as the price of not discovering the divergence at integration.

## Healthcare, privacy, security, and data impact

Positive. Every safety invariant that could otherwise be an unwritten convention
is a schema constraint with a negative fixture proving it is enforced: draft
labelling, absence of clinical recommendation, synthetic-only sourcing, complete
grounding, human-only approval, and audit events that cannot carry narrative
content.

## Validation evidence

`node scripts/validate-contracts.mjs` — 48 checks, 48 passed, exit code 0
(2026-08-12 integration run). Covers 10 schema compilations, 8 valid examples,
19 negative fixtures asserted to fail for their recorded reason, 1
cross-field-only fixture, and 10 cross-field rules.

## Supersedes

None.
