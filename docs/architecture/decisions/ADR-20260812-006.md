# ADR-20260812-006 — Configuration and environment values are separated by schema

**Status:** Accepted

**Owner:** Trinity

**Requirement IDs:** REQ-CFG-001, REQ-CFG-002, REQ-CFG-003, REQ-CFG-004, REQ-CFG-005, REQ-VAL-003

## Context

Harborlight Children's Health is an illustrative example, not the product. The
charter requires that reusable structure be separated from example values, that
another organization can be added without touching core logic, and that
credentials never enter the repository.

The failure mode is well known and quiet: someone pastes a working endpoint or
key into an example configuration to unblock a demonstration, it is committed,
and nobody notices because the file is "just an example". A convention documented
in a README does not stop this. A scan after the fact only catches the patterns
it knows.

## Decision

Four layers, with the boundary enforced by the schema rather than by convention:

1. **Contract** — `contracts/schemas/organization-config.schema.json`. Structure
   only, no example values.
2. **Organization pack** — `config/organizations/{org}/organization.json`.
   Naming, personas, safety copy, workflow scope, illustrative baselines. This is
   the only layer an adopter edits to add an organization.
3. **Environment bindings** — the `environmentBindings` block in the pack maps a
   logical dependency to an environment *variable name*, never to a value. Every
   entry must match `^[A-Z][A-Z0-9_]{2,63}$`, so committing a URL, an endpoint,
   a connection string, or a key produces a schema failure.
4. **Runtime values** — supplied by the environment, documented by name only in
   `config/environments/.env.example`, never committed.

`config/organizations/harborlight/organization.json` is simultaneously the
shipped example pack and the validated example for the configuration contract.
There is one file, not a copy under `contracts/examples/` that can drift.

Required-value coverage is enforced positively: `disclaimerBody` is required with
a minimum length, so an empty or omitted disclaimer fails validation instead of
silently rendering nothing.

Core logic reads only through the contract. No organization name, unit name,
role label, endpoint, or baseline figure is hardcoded.

## Alternatives

- **Single configuration file including endpoints.** Rejected. It puts the
  credential-shaped values in the committed artifact by design.
- **README convention plus a secret scanner.** Rejected as the primary control.
  A scanner is a useful backstop, kept as `npm run scan:secrets`, but it is
  pattern-based and cannot be the boundary.
- **Copy the example pack into `contracts/examples/`.** Rejected. Two files that
  must agree will eventually disagree.
- **Optional disclaimer with a code-side default.** Rejected. A default in code
  is a place where the disclaimer can be removed by configuration without a
  validation failure.

## Consequences

- A committed endpoint or credential in an organization pack is a validation
  failure, before review and before any scan.
- Adding an organization is a new directory plus environment values; no core
  logic changes.
- Deployment requires a documented environment set. `config/environments/.env.example`
  is the checklist and carries names and placeholders only.

## Healthcare, privacy, security, and data impact

Positive on the security axis. The most common accidental-disclosure path for a
prototype repository — a real endpoint or key pasted into an example — becomes a
build failure rather than a commit. The organization pack also asserts
`syntheticOnly`, so a pack pointing at non-synthetic data is refused.

## Validation evidence

`node scripts/validate-contracts.mjs` — fixtures
`organization-config-embedded-endpoint.json` (refused: a literal endpoint where a
variable name is required), `organization-config-missing-disclaimer.json`
(refused: required disclaimer absent), and
`organization-config-non-synthetic-data.json` (refused: `syntheticOnly` not
`true`). The Harborlight pack validates in place at
`config/organizations/harborlight/organization.json`.

`node scripts/scan-secrets.mjs` — 120 files and 15323 lines scanned with 11
rules and no documented allowance, 0 findings, exit code 0 (2026-08-12).
`tests/security/secret-exposure.test.mjs` asserts the scanner still detects
twelve credential-shaped and identifier-shaped values that are assembled at run
time rather than committed.

`node scripts/scan-secrets.mjs` — no credential, connection string, or direct
identifier pattern found in tracked files.
