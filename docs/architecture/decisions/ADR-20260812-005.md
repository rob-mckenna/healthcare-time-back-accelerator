# ADR-20260812-005 — camelCase field naming across all shared contracts

**Status:** Accepted

**Owner:** Trinity

**Requirement IDs:** REQ-VAL-001, REQ-AGT-001, REQ-AGT-003

## Context

The design review surfaced two naming conventions in parallel: `snake_case` from
the agent side, reflecting common practice in model tooling and evaluation
harnesses, and `camelCase` from the data and experience sides, reflecting FHIR
and Power Platform practice. Mixed conventions across contracts produce a
translation layer at every boundary, and translation layers are where fields get
dropped without anyone noticing.

The source data in this slice is FHIR-shaped, and FHIR uses `camelCase`.

## Decision

Every property name in every contract under `contracts/schemas/` is `camelCase`.

Identifier *values* keep their existing prefixed uppercase forms
(`SYN-PAT-…`, `SYN-ENC-…`, `SYN-BDL-…`, `ART-…`, `GEN-…`, `APR-…`, `AUD-…`,
`USR-…`, `CORR-…`) because their shape is a validation signal, not a naming
style. Enumerated values stay uppercase with hyphens (`APPROVED-SIMULATED`,
`E-GROUNDING-FAILURE`) so a value is never mistaken for a property name.

Environment variable names stay `SCREAMING_SNAKE_CASE`, matched by
`^[A-Z][A-Z0-9_]{2,63}$`, because that is the platform convention and because the
distinct shape is what lets the configuration schema tell a variable name from a
literal value.

Schema file names are `kebab-case.schema.json`.

## Alternatives

- **`snake_case` everywhere.** Rejected. It fights the FHIR-shaped source data,
  which is the largest body of field names in the slice.
- **Convention per boundary with a mapping layer.** Rejected. It adds a component
  whose only job is to be a place where fields are lost.

## Consequences

- No translation layer between the source bundle, the agent input, and the
  experience layer.
- Agent instructions must specify `camelCase` explicitly, because model tooling
  conventions pull the other way.
- One consistent rule that can be checked by reading any schema.

## Healthcare, privacy, security, and data impact

Indirect but real. Removing per-boundary field translation removes a class of
silent field-drop defect, which in this slice would mean a safety flag or a
source reference disappearing between components without an error.

## Validation evidence

`node scripts/validate-contracts.mjs` — all 10 schemas compile and all 8 valid
examples validate under `additionalProperties: false`, which means every
property name in every example matches its schema exactly. A casing deviation
would surface as an unevaluated-property failure.

## Supersedes

None.
